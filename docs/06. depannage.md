# Dépannage

Ce guide s'adresse d'abord à l'agent·e M&E. Les sections marquées **Technique** sont destinées à la personne qui a installé le poste.

## 1. L'application ne s'ouvre pas

1. Fermer puis rouvrir le dossier du projet dans VS Code : l'application démarre à l'ouverture.
2. Attendre une minute : le démarrage peut prendre jusqu'à 45 secondes.
3. Ouvrir manuellement l'adresse `http://127.0.0.1:8501` dans le navigateur.
4. Si la page reste vide, contacter la personne technique en lui indiquant l'heure du problème.

**Technique :**
- Les journaux de démarrage sont dans `outputs/logs/`.
- L'API écoute sur le port 8000 et Streamlit sur le port 8501. Si un autre programme occupe un port, l'arrêter, puis relancer la tâche VS Code « M&E : démarrer Streamlit à l'ouverture (si activé) ».
- Si le message indique qu'une API répond déjà sur le port 8000 sans accepter la clé, fermer l'ancienne API (processus Python) puis relancer.

## 2. Message de clé API refusée ou absente

- La clé est enregistrée dans les variables d'environnement du compte Windows (`M_E_API_KEY`), jamais dans le dépôt.
- **Technique :** relancer la tâche « M&E : configurer le mode de ce poste », saisir de nouveau la clé, puis fermer et rouvrir VS Code pour que la variable soit prise en compte.

## 3. Le nettoyage échoue ou signale des erreurs

- Vérifier que l'export Kobo **et** son questionnaire (XLSForm) sont bien dans la zone de dépôt (`zone_depot/`) et qu'ils correspondent à la même enquête.
- Fermer Excel : un fichier ouvert dans Excel peut bloquer la lecture.
- Lire le résumé des contrôles : une colonne manquante ou renommée dans l'export est la cause la plus fréquente.
- Le détail est dans le rapport de nettoyage (« Mes résultats »).

## 4. Un livrable n'apparaît pas dans « Livrables du projet »

- La liste n'affiche d'abord que les livrables principaux. Activer **« Afficher les fichiers techniques »** pour voir les autres (base SQLite, journal, modèle, fiche de l'enquête).
- Si le dossier `outputs/` est vide, l'application montre le jeu de démonstration (`outputs_demo/`).
- Un résultat apparaît seulement après l'étape qui le produit : nettoyage → base → analyse → ciblage → dashboard.

## 5. Le rapport d'analyse ou le dashboard est vide ou incomplet

- Vérifier que le nettoyage puis l'import dans la base ont été faits pour l'enquête active.
- Régénérer l'analyse, puis le dashboard : les alertes sont recalculées à chaque génération.
- Le dashboard est autonome et fonctionne hors connexion. Sans internet, la carte affiche un fond gris avec les zones, sans fond de carte.

## 6. Le modèle Power BI ne se charge pas

- Ouvrir le fichier `.pbix` avec **Power BI Desktop** (gratuit, Windows). Il ne s'ouvre pas dans le navigateur.
- Si Power BI ne trouve pas les données : **Accueil > Transformer les données > Paramètres de la source de données**, puis pointer vers `outputs/donnees_dashboard.csv` et `outputs/alertes_dashboard.csv`.
- Cliquer sur **Actualiser** après chaque nouvelle génération du dashboard.
- Si une mesure signale qu'une colonne est introuvable, vérifier que la première ligne du CSV est bien utilisée comme en-têtes.

## 7. Accents illisibles dans un fichier CSV

- Ouvrir le CSV dans Excel via **Données > À partir du texte/CSV** en choisissant l'encodage **UTF-8**.

## 8. Lenteur ou blocage

- Fermer les onglets inutiles de l'application et patienter pendant un nettoyage ou un entraînement (les gros fichiers prennent plusieurs minutes).
- **Technique :** vérifier la place disque disponible : `outputs/` contient une base SQLite et des CSV volumineux (environ 120 Mo).

## 9. Réinstaller proprement

**Technique :**
1. Créer l'environnement virtuel : `python -m venv .venv`.
2. L'activer, puis `pip install -r requirements.txt`.
3. Relancer la tâche de configuration du poste.
