# Mémo : Conventions de Commit Professionnelles

| Préfixe | Quand l'utiliser ? | Exemple concret |
| :--- | :--- | :--- |
| **`feat:`** | Ajout d'une nouvelle fonctionnalité majeure ou d'un livrable visible. | `feat: implementation de l'API CRUD FastAPI` |
| **`fix:`** | Correction d'un bug ou d'une erreur dans le code. | `fix: correction des valeurs NaN dans la table menage` |
| **`chore:`** | Tâches de maintenance, configuration ou gestion des dépendances. | `chore: initialisation de l'arborescence et requirements.txt` |
| **`docs:`** | Rédaction ou modification de documentation. | `docs: mise à jour du README et de la problématique métier` |
| **`refactor:`** | Restructuration du code sans changer son comportement. | `refactor: modularisation du script de nettoyage SQL` |
| **`style:`** | Modifications de forme qui n'affectent pas le code (espaces, formatage). | `style: formatage du code python selon la norme PEP8` |
| **`test:`** | Ajout ou modification de tests unitaires/techniques. | `test: ajout de tests pour les routes POST de l'API` |
